# VP-12: Cancellation-propagation adoption spike

## Status

Implementation and independent review complete; merge gate pending.

## Goal

Execute the compatibility spike that ADR-0003 scheduled for the request-level
cancellation gap: establish whether the pinned QwenPaw dependency chain can
adopt the MCP Python SDK dispatcher cancellation behavior (python-sdk PR
2838), and keep a living signal that fires when upstream adoption becomes
possible.

## Dependencies

- ADR-0003 (`docs/decisions/0003-cancellation-owned-by-client-sdk.md`):
  the spike is its explicitly deferred action item.
- MCP Python SDK `2.0.0` (released 2026-07) contains the dispatcher v2
  client whose `cancel_on_abandon` sends `notifications/cancelled` when a
  request is abandoned. The pinned chain resolves `mcp` `1.29.0` (v1 line,
  maintenance mode).
- The pinned chain pulls `mcp` transitively through `agentscope`
  `2.0.4.post1`, whose requirement is `mcp<2.0.0`; that constraint is the
  adoption blocker, not QwenPaw code.

## Product contract

- Facts and evidence only. This package changes no runtime behavior, no
  stable claim, and no pinned revision.
- No monkey-patching of QwenPaw, agentscope, or MCP SDK internals, per
  ADR-0003.
- The wire-level gap statement (`cancellation_propagated=0` for the pinned
  chain) continues to come from the VP-02 hermetic probe; this package does
  not re-implement it.
- The new adoption probe is an advisory canary: it must fail loudly when
  upstream adoption becomes possible, and it must never rewrite the stable
  compatibility claim by itself.

## Acceptance

- `compat/cancellation_adoption_probe.py` records, as schema-validated
  evidence (`scenario: cancellation`): the pinned agentscope/mcp versions
  from `compat/qwenpaw-app/uv.lock`, the pinned agentscope's immutable
  `mcp` requirement observed from PyPI, the latest agentscope release's
  `mcp` requirement, and the latest `mcp` release version. Metrics include
  `cancellation_probe_completed=1`, `cancellation_propagated=0`,
  `fix_released_upstream=1`, `pinned_chain_adopts_fix=0`, and
  `agentscope_allows_mcp2` (0/1).
- `scripts/run-vp12.sh` runs the probe, validates the evidence against
  `schemas/evidence.schema.json`, and asserts the adoption-blocked state so
  the script fails loudly once `agentscope_allows_mcp2` becomes 1.
- The probe is wired into the advisory candidate CI lane.
- ADR-0003 records the spike outcome: the fix exists upstream, adoption is
  blocked by the pinned `agentscope` `mcp<2.0.0` requirement, and the
  durable workflow lifecycle remains the product answer for cancellation.
- `docs/DEMO-SCENARIOS.md` and `docs/STATUS.md` wording about the
  cancellation gap stays accurate; the ledger marks this package in
  progress at implementation time and complete after merge.
- `scripts/check-repository.sh` passes; CI stable lanes pass; independent
  GLM-5.2 review of the exact implementation head returns no P0/P1
  findings.

## Non-goals

- Re-testing the wire on the pinned chain (already covered by VP-02).
- Upgrading `mcp`, `agentscope`, or the QwenPaw pin; building an SDK-v2
  client lane; any product claim about cancellation.
- Monkey-patching or forking any upstream package.
