# VP-08: Durable workflow control

## Status

Implementation complete; independent review and merge gates pending.

## Goal

Give QwenPaw an honest long-running Vyane execution lifecycle without claiming
that stopping a request-bound chat turn cancels server-side work.

## Product contract

- Request-bound `route`, `dispatch`, `failover`, and `review` retain finite
  timeouts. A local QwenPaw stop is not reported as server cancellation.
- Durable execution uses Vyane's explicit workflow control tools:
  `vyane_workflow_submit`, `vyane_workflow_status`, and
  `vyane_workflow_cancel`.
- The plugin invokes durable control through QwenPaw's governed
  `DriverManager`, not through model-selected tool arguments. This keeps the
  caller-owned workflow id, bounded workflow source, and cancellation target
  deterministic.
- Submit creates one fixed read-only workflow step from a validated target and
  the original user task. Status and cancel accept only a canonical lowercase
  UUIDv7.
- Repeated cancel requests are idempotent. An `outcome_unknown` submit requires
  status with the same caller id before any identical retry.

## Acceptance

- Deployment policy separately authorizes durable workflow control and its
  allowed target profiles.
- User task text never enters a system prompt, log, evidence document, or
  error response.
- A real pinned QwenPaw app and pinned vyane-rs daemon prove submit, status,
  cancellation, repeated cancellation, and terminal status through the
  persisted MCP Driver.
- The daemon, QwenPaw app, MCP process, workflow worker, and synthetic endpoint
  all terminate within bounded cleanup windows.
- Evidence distinguishes request cancellation, workflow cancellation requested,
  and terminal workflow cancellation.
- Stable and candidate compatibility gates continue to pass.

## Non-goals

- Patching MCP Python request-id internals.
- Claiming support for the MCP Tasks extension before both pinned endpoints
  advertise and pass that protocol.
- General user-authored workflow TOML or arbitrary prompt-file upload.
- UI, installation, recording, and competition materials.

## Verification

- Repository, policy, operation-result, and pinned QwenPaw structural contracts
  pass.
- The stable lane passed the real headless QwenPaw and durable-workflow
  integration against vyane-rs `4848ec4f9d0b740fd8dc5f5586bc30111dc3d373`
  with rmcp `3.0.0`.
- The moving candidate lane and the same real durable-workflow lifecycle passed
  against vyane-rs `70649da8faa2e686a583072affcf75f7e718a381`.
- The lifecycle reached the synthetic provider, accepted two idempotent cancel
  requests, reached terminal `cancelled`, leaked no task marker into runtime
  logs, and reaped QwenPaw, MCP, and daemon processes.
