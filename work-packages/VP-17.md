# VP-17: Stable upstream lock promotion refused (vyane-rs rmcp 3.3.0)

## Status

Evaluated on 2026-10-22 against vyane-rs `main`
`03ebd40374ff37927c2d440beda7daa23f1d2aa4`. The stable lock does not move.
It remains vyane-rs `03dbd2fd1f1a3f7d6d7f8aa9396c6ce55b5d22f0` and rmcp
`3.0.1`. The QwenPaw pin does not move.

This package also records two canary-maintenance changes that do not depend
on promotion: the candidate image now uses uv `0.13.4`, and a failed
schedule or manual candidate run opens one GitHub issue.

## Goal

Evaluate the current `vyane-rs` main as a stable-lock candidate and promote
`upstreams.lock.json` only if every stable gate passes at that exact
revision. The candidate's pinned `Cargo.lock` resolves a single rmcp version,
`3.3.0`.

## Product contract

- The stable lock moves only on evidence produced at the exact new revision.
  Compatibility is never claimed from version ranges.
- The candidate lane remains advisory. Promoting the lock would not have
  changed that, and refusing promotion does not either.
- If any stable gate fails at the candidate revision, the lock stays put and
  the failure is the written conclusion of this package.
