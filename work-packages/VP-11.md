# VP-11: Product documentation introduction

## Status

Proposed. Not yet scheduled; recorded so the next planning round can pick it
up without re-scoping. Requested by the repository owner on 2026-07-30 ("把
文档介绍也上一上"), timing left to engineering judgment.

## Goal

Give Vyane Paw a product-facing introduction that matches the verified
engineering state: what the product is, the two supported QwenPaw extension
surfaces, the request-bound and durable execution modes, the safety and
privacy boundaries, and an honest capability/non-capability list backed by
committed evidence.

## Scope proposal

- Bilingual (`README.md` / `README.zh-CN.md`) editorial expansion beyond fact
  alignment: product story, architecture summary, quick-start shape, and the
  evidence-backed capability list (route/dispatch/failover/review, durable
  workflow lifecycle, capability probe results).
- A "What Vyane Paw does not claim" section derived from
  `docs/MCP-COMPATIBILITY.md` (no MCP Tasks, no gateway, no remote transport).
- Optional preparation of a docs.zleo.ai-ready page bundle (content only,
  sanitized) so a later publishing decision is a toggle, not a rewrite.

## Preconditions

- VP-10 (stable lock promotion) merged, so the documented baseline is the
  current one.
- Explicit owner review of the disclosure boundary before anything targeted
  at docs.zleo.ai leaves the repository; the repository stays private until
  then (`AGENTS.md`).
- All user-facing paths, names, and screenshots remain synthetic per the
  safety boundary.

## Non-goals

- Publishing to docs.zleo.ai itself (separate owner decision).
- Screenshots, recordings, or competition material (VP-04 stays deferred).
- Any change to product behavior; this package is documentation only.

## Suggested timing

Immediately after VP-10 merge, as a documentation-only package with the
standard gates (`check-repository.sh`, documentation-delta independent
review).
