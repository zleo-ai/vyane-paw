# VP-15: Durable workflow output retrieval

## Status

Proposed. Approved by the repository owner on 2026-07-30 as a two-phase
direction; phase one belongs to the vyane-rs repository and must land first.

## Goal

Let a user retrieve the bounded output of a succeeded durable workflow
through the `/vyane` product surface, completing the durable lifecycle
(submit → status → result) without weakening the redaction boundary.

## Background

VP-08 delivers submit/status/cancel, but the pinned vyane-rs `WorkflowView`
deliberately projects only `caller_id`, `state`, and `failure_code` — a
succeeded workflow exposes no output to the MCP client, so Vyane Paw cannot
return anything. Confirmed at `319b9da` (`crates/vyane-mcp/src/lib.rs`,
"Fully bounded … Deliberately excludes ownership, controller, lease,
authentication, paths, prompts, and raw error fields").

## Phase plan

1. **vyane-rs (separate repository, its own work package)**: add a bounded
   output projection to the workflow lifecycle view — allowlisted fields
   only, with an explicit byte bound, keeping the existing exclusions
   (paths, prompts, raw errors, ownership). The MCP tool surface gains the
   projection without breaking the current view.
2. **vyane-paw (this package)**: project the new fields in
   `result_contract.py` through the existing allowlist pattern, present them
   for `workflow-status` on `succeeded`, extend the operation-result schema
   (minor, additive), and prove the end-to-end path in
   `compat/qwenpaw_durable.py` (submit → succeeded → bounded retrieval) with
   committed evidence.

## Preconditions

- Phase one merged in vyane-rs and the stable lock promoted to a revision
  containing it (VP-10 process).
- Size bound enforced at both layers; task text and prompt content never
  enter evidence or logs.
- If phase one does not land, this package stays proposed and the durable
  lifecycle remains status-only.

## Non-goals

- Free-form workflow TOML or arbitrary prompt-file upload (VP-08 non-goals
  stand).
- Streaming output, incremental progress, or output for non-succeeded
  states.
- Any change to request-bound modes.

## Verification (phase two, when scheduled)

- `bash scripts/check-repository.sh`
- `bash scripts/run-vp08.sh` with the retrieval chain included
- Schema validation and independent GLM-5.2 review per standard gates.
