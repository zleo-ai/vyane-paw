# VP-03: Policy and evidence contracts

## Status

Complete — merged by PR #4 after exact-HEAD self-hosted CI and independent
GLM-5.2 review.

## Goal

Turn the draft schemas into enforced, versioned contracts.

## Acceptance

- Tool allowlists are applied before execution.
- Raw evidence cannot be marked publishable automatically.
- Schema validation is part of CI.
- Migration rules exist before a schema-breaking change.

## Runtime-policy increment

- Load a deployment-owned JSON policy from `VYANE_PAW_POLICY`; an explicitly
  configured policy that cannot be read or validated fails closed.
- Apply tool, failover, broadcast, target, and parallelism decisions after
  command parsing and before any agent context is injected.
- Bind the authorized command to a request-scoped QwenPaw tool whitelist so
  the agent sees only the one required Vyane MCP tool for that turn.
- Keep the built-in fallback policy bounded to route and dispatch. Named
  failover and broadcast require explicit policy authorization.
- `dispatch` is deliberately fixed to Vyane `target=auto`; `allowed_targets`
  applies only to explicit failover profile selectors and review targets.
  The selected failover profile owns its internal fallback chain in Vyane.
- Never include the policy path or rejected target names in user-visible
  errors.
- Normalize the selected Vyane MCP `ToolResponse` before it reaches the model
  into `operation-result.schema.json`. Completed receipts remain final,
  broadcast partial success is explicit, and raw upstream errors are reduced
  to bounded codes. Completed data is projected through an allowlist before it
  reaches the model.
- Require a separate human approval record and source digest before sanitized
  evidence can validate as publishable; repository generators remain
  sanitized-only.
- Apply `docs/SCHEMA-MIGRATIONS.md` before any breaking policy, result, or
  evidence contract change.
