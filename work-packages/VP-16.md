# VP-16: Public repository hosted-only CI boundary

## Status

In progress. The repository runner remains registered but offline until the
hosted workflow patch is reviewed, merged, and green on `main`.

## Goal

Move every workflow in the public repository to GitHub-hosted runners and
remove the repository-level self-hosted runner registration after hosted CI has
proved the replacement path.

## Finding and threat boundary

The repository is public. Before VP-16, `quality.yml` ran fork-controlled pull
request code on `[self-hosted, vyane-paw]`. GitHub schedules the job before any
in-job guard can inspect the actor or ref, so a script-level owner check cannot
make that runner safe.

Security invariant:

- every public-repository workflow uses the exact hosted runner allowlist;
- the public repository contains no `self-hosted` marker or custom runner
  label;
- `pull_request_target`, `workflow_run`, `repository_dispatch`, reusable
  workflow jobs, and dynamic `runs-on` expressions fail the static boundary;
- checkout credentials are not persisted and setup-uv cache upload is off;
- no public workflow receives repository secrets;
- lightweight local CI, if needed later, lives in a separate private control
  repository and is never a public-PR fallback or required check.

Legitimate behavior to preserve:

- repository, product-entry, moving-candidate, headless QwenPaw,
  durable-workflow, and capability probes remain available;
- the advisory candidate lane remains non-blocking in the pull-request flow;
- the moving-candidate probe remains scheduled and manually runnable;
- all Python environment setup remains pinned to full action SHA + uv version.

## Patch strategy

1. Change every job in `quality.yml` and `candidate-compatibility.yml` to
   `ubuntu-24.04`.
2. Install uv through the full-SHA setup action with cache upload disabled.
3. Add a stdlib-only checker and adversarial self-test for all workflow files,
   events, runner labels, expressions, and reusable-workflow jobs.
4. Run repository validation and actionlint locally, then open a draft PR.
5. Require hosted PR checks and an independent security review.
6. Merge only when evidence is green; verify the hosted `main` run; then delete
   the exact offline repository runner registration.

## Acceptance

- All workflows and all jobs use `ubuntu-24.04`.
- No workflow file contains `self-hosted` or another runner label.
- Static tests reject the old shape, custom labels, dynamic expressions,
  `workflow_run`, `pull_request_target`, `repository_dispatch`, and reusable
  workflow jobs.
- `scripts/check-repository.sh` passes.
- Official actionlint reports zero errors.
- Hosted checks pass on the draft PR and on merged `main`.
- GitHub reports zero repository-level self-hosted runners after cutover.

## Non-goals

- Running public pull-request code on ROG/WSL under any event or guard.
- Building the future private lightweight-CI control repository in this patch.
- Adding provider credentials, private endpoints, model review, GPU work, or
  internal network access.
- Changing repository visibility or introducing new branch-protection rules.
