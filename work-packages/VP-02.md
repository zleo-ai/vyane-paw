# VP-02: Demonstrable product flows

Status: first hermetic increment complete — local and self-hosted CI passed,
with official GLM-5.2 independent review. Full product integration and the
QwenPaw cancellation-propagation gap remain open.

## Goal

Implement the three scenarios in `docs/DEMO-SCENARIOS.md`.

## Scope

- Use the pinned, unmodified QwenPaw stdio MCP client.
- Use local synthetic OpenAI-compatible endpoints without credentials.
- Prove deterministic routing, real failover, parallel broadcast, and
  per-target failure isolation.
- Probe timeout and cancellation behavior without overstating unsupported
  propagation.
- Produce one sanitized evidence document per product flow and reliability
  probe.

## Acceptance

- Route, failure-aware dispatch, and multi-model review run end to end.
- Each scenario has a synthetic fixture and machine-readable evidence.
- Metrics are measured rather than estimated.
- QwenPaw presents failures and limitations clearly.

## Current evidence

The first local fixture passed on 2026-07-29:

- review-stage routing selected the declared reviewer profile without returning
  the task text;
- a deterministic primary HTTP failure fell back to the backup target;
- a mixed broadcast preserved one success while isolating one failed target;
- a bounded slow target produced a recorded timeout;
- two synthetic reviewers overlapped with observed concurrency of two;
- cancelling QwenPaw's local `call_tool` coroutine did not propagate an MCP
  cancellation notification, so the Vyane run continued to success.

The last point is a verified limitation, not a successful cancellation claim.
The route, failover, failure-isolation, timeout, cancellation, and broadcast
records in `evidence/vp02-*.json` come from one ordered run, so their timestamps
preserve execution order. Failover latency is not inflated by the later
reliability probes.

The exact implementation revision passed the private repository's dedicated
self-hosted CI and independent review through the official GLM Coding Plan.

## Reproduction

```bash
./scripts/run-vp02.sh
```

The script first preserves the VP-01 compatibility gate, then runs all three
VP-02 scenarios against process-local synthetic endpoints. It makes no paid
model call and requires no provider credentials.
