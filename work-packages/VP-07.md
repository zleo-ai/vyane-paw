# VP-07: Headless QwenPaw application integration

## Status

Implementation and gates complete; PR merge pending.

## Goal

Prove the Vyane Paw boundary through a real pinned QwenPaw application process,
not only through an isolated MCP client module or plugin contract doubles.

## Acceptance

- A test starts the pinned QwenPaw FastAPI application with isolated working,
  secret, backup, and plugin data and with credential-bearing environment
  variables removed.
- The test installs the tracked Vyane Paw plugin through QwenPaw's runtime
  plugin API and configures the pinned vyane-rs MCP server through QwenPaw's MCP
  API.
- A local synthetic OpenAI-compatible model submits one deterministic Vyane
  tool call; no paid or external model is invoked.
- A `/vyane route` request travels through the real console API, slash-command
  registry, plugin context injection, final tool whitelist, QwenPaw MCP driver,
  pinned vyane-rs server, and result middleware.
- The model-visible tool surface contains exactly the one namespaced Vyane tool
  authorized for the selected command; unrelated QwenPaw and Vyane tools are
  absent.
- The result is bounded, records that route mode did not execute a target, and
  does not expose absolute paths, credentials, endpoints, or raw provider
  errors.
- The QwenPaw app, synthetic model server, and vyane-rs MCP child all terminate
  within bounded cleanup windows.

## Non-goals

- Browser or UI automation.
- Installation or end-user packaging.
- Screen recording or competition material production.
- Paid model quality evaluation.
- Long-task cancellation semantics, which remain a separate capability package.

## Implementation notes

- The application environment is resolved from a dedicated `uv.lock` whose
  QwenPaw Git source is pinned to the same revision as `upstreams.lock.json`.
- The integration uses two bounded application phases: install and persist the
  plugin through the runtime API, then restart into the installed state before
  submitting the command. This avoids treating a transient pre-reload
  workspace as proof that a hot-installed slash command survived.
- The pinned host's generic context-injection helper currently creates a
  system-role input message that AgentScope rejects. Vyane Paw therefore adds
  its validated current-turn contract through AgentScope's native system-prompt
  middleware and keeps the original user task exclusively in the user message.
- The command disables the generic Skill metatool for its current turn and
  applies QwenPaw's final request-scoped tool whitelist, leaving only the
  selected namespaced Vyane MCP tool visible to every model iteration.
- A following ordinary turn proves the request-scoped tool and prompt contract
  are cleared, and both the installation-phase and execution-phase MCP
  processes must be observed and reaped within bounded polling windows.
