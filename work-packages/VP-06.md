# VP-06: Stable and candidate compatibility lanes

## Status

Implementation in progress.

## Goal

Detect vyane-rs integration drift early without weakening the reproducible
Vyane Paw baseline.

## Acceptance

- The stable lane always checks out the exact QwenPaw and vyane-rs revisions
  recorded in `upstreams.lock.json` and remains a required quality gate.
- The candidate lane resolves the current public vyane-rs `main`, immediately
  freezes that run to the resolved commit, and records the actual commit in
  sanitized runtime evidence.
- Stable and candidate checkouts, binaries, and evidence paths do not overlap.
- Automated candidate execution stays inside a capability-dropped container
  with a read-only archive of tracked repository files, a per-job writable
  runtime mount, no Docker socket, and no persisted checkout credential.
- Host bypass-domain lists are not forwarded; only loopback is exempted from
  credential-free proxy variables. Public network access remains available for
  resolving and building the moving candidate.
- The canary uses a fixed, read-only Rust toolchain. A candidate that requires a
  different toolchain fails visibly instead of installing one at runtime.
- Both lanes verify the resolved `rmcp` version, exact MCP tool set, one safe
  call, one bounded rejection, and clean client/server shutdown.
- Candidate failures are visible canary results but do not redefine or silently
  invalidate the stable compatibility claim.
- The moving canary runs on Vyane Paw changes, has a best-effort daily schedule,
  and supports manual dispatch so vyane-rs drift can be detected without
  waiting for this repository to change.

## Verification

- stable: `scripts/run-vp01.sh`
- candidate: `scripts/run-vp06.sh`
- isolated CI candidate: `scripts/run-vp06-container.sh`
- runtime evidence: `runtime/evidence/vp01-stable.json` and
  `runtime/evidence/vp01-candidate.json`

Candidate evidence is intentionally not tracked because the source branch is
moving. A promotion to stable requires an explicit update to
`upstreams.lock.json`, full required CI, and independent review.
