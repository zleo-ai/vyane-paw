# VP-01: QwenPaw ↔ rmcp 3.0 compatibility

Status: implementation verified locally; CI and independent review pending.

## Goal

Prove that an unmodified pinned QwenPaw MCP client can use the pinned
`vyane-rs` stdio server.

## Scope

- Pin exact QwenPaw and vyane-rs revisions.
- Launch and shut down the stdio server cleanly.
- Complete initialization and tool discovery.
- Execute one safe tool call and one deterministic error case.
- Produce a sanitized evidence record.

## Acceptance

- Automated test exits successfully on the supported development platform.
- Expected tool names are asserted, not only counted.
- Failure output contains no credentials, user paths, or private identifiers.
- Reproduction steps work from a clean checkout.
- An independent reviewer checks the evidence and compatibility claim.

## Current evidence

The first local run passed on 2026-07-29:

- pinned QwenPaw client source loaded without modification;
- pinned `vyane-rs` built with `rmcp` 3.0.0;
- Python MCP 1.29.0 completed the legacy initialization lifecycle;
- the exact nine-tool set was discovered;
- one safe call succeeded and one invalid call was rejected;
- the client and server process closed cleanly.

See `evidence/vp01-baseline.json`. This proves the isolated client/server
boundary only; it does not yet prove full QwenPaw application integration.

## Reproduction

```bash
./scripts/run-vp01.sh
```

The script checks out the exact revisions from `upstreams.lock.json`, builds
`vyane-rs`, loads QwenPaw's unmodified `StdIOStatefulClient` source, and writes
sanitized runtime evidence under the ignored `runtime/` directory.

## Non-goals

- Remote transport.
- MCP Tasks.
- Permanent gateway.
